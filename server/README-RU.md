# VK Games: «Открыть все карты» — 10 голосов

Интеграция подготовлена для приложения **54870403**. Серверный товар —
`unlock_all_maps`, цена — **10 голосов**, покупка разовая. Она открывает только
карты кампании и выбор уровней; не выдаёт звёзды, монеты, транспорт, достижения
или отметки о прохождении.

## Текущий статус

Платёжный сервер развёрнут в российском Yandex Cloud, но оставлен в безопасном
закрытом режиме:

- Cloud Function: `traffic-pulse-vk-payments`;
- HTTPS endpoint и будущий callback:
  `https://functions.yandexcloud.net/d4eo58crqj6cu6fk4hmg`;
- до настройки кабинета VK публичный вызов функции отключён, чтобы не было
  посторонних вызовов и расходов;
- данные заказов и прав хранятся в YDB `fliprider-rustore-dev`, в отдельных
  таблицах `tp_vk_orders` и `tp_vk_entitlements`;
- сервисный аккаунт функции имеет только роль `ydb.editor` на этой базе;
- `VK_PAYMENTS_LIVE=false`, а в `payments-config.js` стоит `enabled:false`.

Поэтому реальные списания сейчас невозможны, предложение покупки скрыто, а
endpoint не принимает анонимный трафик.
Синтетический закрытый smoke-test прошёл: проверены цена 10 голосов,
идемпотентность callback, разделение аккаунтов, восстановление права и возврат.
Он не заменяет настоящий тестовый платёж в кабинете VK. Режим
`--synthetic-test` сначала снимает публичный доступ с функции, генерирует новый
тестовый ID и печатает его как `synthetic_user`. После проверки обязательно
публикуется secretless-версия командой `--private-disabled`. Публичный вызов
разрешается отдельно только непосредственно перед настройкой callback VK. Синтетический режим нельзя запускать на боевой
функции после включения реальных платежей.

Cloudflare обслуживает только публичные файлы игры и изображение товара.
VK ID, launch-параметры, заказы и права доступа туда не передаются и там не
хранятся.

## Серверная реализация

Активный обработчик находится в `server/yandex/`:

- `index.py` — HTTP-вход Cloud Function;
- `billing_core.py` — проверка подписи VK и переходы состояний заказа;
- `ydb_store.py` — транзакционная запись заказов и прав;
- `bootstrap.sql` — схема YDB;
- `deploy.py` — воспроизводимое развёртывание из авторизованного Cloud Shell;
- `smoke.py` — закрытый синтетический тест.

Прямой URL функции выбран специально: отдельный API Gateway не нужен.
Маршрут определяется типом тела запроса. Формы VK обрабатываются как callback,
JSON от клиента — как проверка права. CORS разрешён только для точного origin
игры. Тела запросов и launch-параметры код не журналирует; уровень логов
функции — только ошибки.

`server/vk-payments.mjs` и локальная SQLite — резервная реализация, не
используемая текущим прод-размещением.

## Что осталось настроить в кабинетах

1. В кабинете VK приложения **54870403** указать точный callback без суффикса:
   `https://functions.yandexcloud.net/d4eo58crqj6cu6fk4hmg`.
2. Включить тестовый режим платежей и добавить тестовый VK ID.
3. Защищённый ключ приложения ввести приватно как `VK_APP_SECRET` в новой
   версии Yandex Function. Не передавать его через Git, клиент, CLI-аргументы
   или историю shell.
4. Оставить `VK_PAYMENTS_LIVE=false` и указать тестовый ID в
   `VK_TEST_USERS`.
5. Непосредственно перед настройкой callback опубликовать secretless/test
   версию и разрешить публичный вызов; затем выполнить настоящий тестовый цикл
   `get_item` → `order_status_change` → проверка восстановления доступа.
6. Только после успешного цикла включить `VK_PAYMENTS_LIVE=true` и
   `enabled:true` в `payments-config.js`, затем обновить статику.

## Клиентская безопасность и трафик

Клиент не делает платёжных запросов на старте игры. Проверка запускается только
при открытии карты кампании, ручном восстановлении покупки и после платёжного
диалога. Успешный серверный результат кэшируется в памяти на 5 минут, а после
сетевой ошибки фоновые повторы блокируются на 30 секунд. Ручное восстановление
может повторить запрос сразу.

Диалог вызывается через VK Bridge, но сообщение об успехе, `order_id` или
локальный флаг сами по себе ничего не открывают. Доступ выдаётся только по
подписанному callback VK, записанному сервером в YDB.

## Обязательный тест перед боевым включением

1. VK показывает товар «Открыть все карты» за **10 голосов**.
2. Отмена и ошибка сервера не открывают карты и не списывают голоса повторно.
3. Успешный тестовый callback открывает карты ровно один раз.
4. Повторный callback идемпотентен; другой аккаунт права не получает.
5. Право восстанавливается после перезапуска и на другом устройстве.
6. Возврат убирает платный доступ при следующей проверке.
7. Поздний уровень не помечает ранние уровни пройденными и не выдаёт награды.
8. После проверки тестовой схемы отдельно подтвердить боевой callback.
