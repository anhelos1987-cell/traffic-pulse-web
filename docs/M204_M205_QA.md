# Traffic Pulse M204–M205 — engineering validation and release gates

Target: VK Games / OK Games web build (`vk-games`). Base: M201. All work is isolated to draft PRs and **is not yet deployed**.

## Milestone M204 — signal feedback and clarity

- Shared H/V and independent J0/J1 signal buttons display a thin progress meter during yellow/all-red transition, sourced from the actual `transitionTimer` and `config.clearance`.
- Progress is quantized to 20 increments and updated on the existing HUD refresh. Repeated unchanged values do not write styles; M205 also avoids the DOM element lookup.
- Canvas and keyboard attempts during clearance explain why the action was rejected, at most once each 1,000 ms. **No input is buffered or replayed**, so switch counts, flow/score and collision rules remain unchanged.
- Existing `aria-busy`, disabled controls and reduced-motion styling are retained.
- Regression coverage: meters for ordinary/J0/J1, reset, no duplicate DOM writes, rejected input throttling, no queued switch, unchanged-stable DOM lookups.

## Milestone M205 — fixed-step CPU/GC cleanup

- Replace per-tick `.filter()` on `this.particles` and `this.pedestrians` with in-place stable compaction.
- Keeps surviving object identity, array identity and order. Particle physics and pedestrian speed/clearance logic are unchanged.
- Both cleanup paths run on nominal 60 Hz simulation ticks; eliminating two transient arrays per typical active tick reduces avoidable garbage pressure (up to ~120 arrays/s in these paths), **not necessarily overall CPU**.
- Stable signal progress skips DOM lookup when its quantized value has not changed.
- Tests exercise the real methods, including 12,000-tick empty scenes, removals with survivor order, crossing speed, crash FX and HUD DOM gating.

## CI evidence

- M204 run [42645282779](https://github.com/anhelos1987-cell/traffic-pulse-web/actions/runs/42645282779): 84/84 Node tests, 10/10 Python tests, syntax and privacy checks PASS.
- M205 run [42646415855](https://github.com/anhelos1987-cell/traffic-pulse-web/actions/runs/42646415855): 91/91 Node tests, 10/10 Python tests, syntax and privacy checks PASS.
- Informational M205 microbenchmark (Node runner, 30,000 ticks, **single sample, noisy**): relative pre-M205 `.filter` / M205 runtime was 1.07x (empty particles), 1.19x (8 particles), 1.03x (empty pedestrians), **0.86x (8 pedestrians)**. V8's native `.filter()` can be faster for populated lists despite extra allocations.
- These microbenchmarks are neither WebGL results nor evidence of a certain frame-rate uplift. The reproducible script is `node scripts/benchmark-m205-hotpaths.mjs`; comparisons are informational, not CI thresholds.

## Platform validation required before release

- [ ] VK and OK desktop/mobile: tap board during clearance; verify no automatic second switch and clear feedback.
- [ ] VK and OK independent J0/J1 Green Wave: separate meter states, both responsive after clearance.
- [ ] Reduced-motion mode, portrait/landscape, small touch targets and browser screen readers.
- [ ] Gameplay sequences: 1-lane, 2-lane, 3-lane, turning, buses, emergency services, pedestrians, roundabout and 30+ minutes of continuous play.
- [ ] Chrome Performance/Memory or remote Safari Web Inspector: representative low-end Android/iPhone measurements with the same route, viewport and DPR for M201 versus M205; record mean/p95 frame time, GC, JS heap, thermal throttling and battery constraints.
- [ ] VK and OK cloud save: immediate app close after campaign/daily/weekly/Green Wave win, rewarded grant, offline recovery and account switch.
- [ ] No duplicate ad rewards or monetization calls, and no visual overlap with native ad banners.
