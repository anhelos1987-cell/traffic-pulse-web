## Added browser regression

After the real game boots, switches a signal, pauses, resumes, receives keyboard input, writes a local checkpoint and reloads:

- For **each** mobile browser viewport (390×844 and 844×390), alternate portrait and landscape **12 times without reloading**.
- Check Canvas backing size and on-screen bounds remain usable, signal touch target stays at least 40 CSS pixels in both dimensions, document does not horizontally overflow, signal remains enabled, render fallback stays absent, and no uncaught page errors occur.
- Desktop 1280×800 still runs the existing smoke.
- The same 13-file VK/OK test ZIP and checksum manifest are generated by CI.

## Verified CI

[Run 42679521352](https://github.com/anhelos1987-cell/traffic-pulse-web/actions/runs/42679521352): **SUCCESS**, 119/119 JavaScript tests, 10/10 Python tests, all 3 Chromium smoke viewports and both 12-rotation cycles passed.

## What this does not prove

- Desktop Chromium device emulation is not a physical iPhone/Android WebView. Safe-area insets, on-screen keyboards, browser chrome, notch handling and touch latency need physical validation.
- A passing smoke test is not a 30-minute performance/memory profile.
- VK/OK real authentication, cloud synchronization, rewarded ads and payments are still manual release blockers.
- This milestone does **not** replace the approved M212 manual test candidate. For the upcoming physical test, use the M212 ZIP and checklist; keep M213 as an optional next cumulative candidate if M212 testing is satisfactory.

**Release decision:** no merge or publication until manual P0/P1 checks and a separate deployment review.
