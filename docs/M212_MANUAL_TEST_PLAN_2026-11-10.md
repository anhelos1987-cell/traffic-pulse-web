## Известные технические ограничения

- **Облако:** VK Bridge Storage не предоставляет атомарный compare-and-swap для указателя сохранения. M209 добавил обнаружение конфликтов и восстановление по живому устройству; при одновременной записи и полной потере всех локальных копий гарантии отсутствуют.
- **CI:** headless Chromium проверяет локальный fallback, но не настоящие вызовы SDK, рекламу и облачное хранилище внутри VK/OK.
- **Производительность:** устранены отдельные временные массивы в симуляции; улучшение FPS на реальном устройстве не доказано до профилирования.
- **Интеграция:** milestone-ветки **накопительные**. Каждый следующий PR уже включает исходники всех предыдущих M-этапов. При стандартном squash merge последовательное объединение всех PR может повторно включать одни и те же изменения. **Предпочтительно проверить итоговый PR #13 и затем объединить только его** в `vk-games`; после этого закрыть ранние PR как superseded. Если во время проверки `vk-games` изменится, сначала согласовать изменения и повторить CI.

## Как зафиксировать дефект

Запишите: **платформа → устройство → версия ветки/сборки → воспроизводимые шаги → ожидалось → фактически → скриншот/видео → console error (если есть)**. Не добавляйте в публичный issue пользовательские идентификаторы, токены, подписанные launch-параметры или содержимое сохранения.
